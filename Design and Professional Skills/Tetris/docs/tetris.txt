Autograder Mechanics and Queue Discipline
How Submissions Are Evaluated
1. Multiple Runs: Every git push runs your player
across several independent games.
2. Secret Random Seeds: Each run generates a
different pseudo-random sequence of tetrominoes.
3. Median Metric: Your recorded score is the
median score across all runs for that commit.
4. Isolated Server State: The test harness
maintains its own copy of game rules and
board.score.
Fair Queuing Algorithm
When busy, the server selects next from the user
whose most recent evaluated run finished longest
ago. Rapid repeated pushes place your newest
commit at the back of your own queue.
Submission Advice
Expect multi-hour queues near the deadline.
Benchmark locally first, push only substantial
improvements, and cancel superseded queued
submissions via the web interface.

Autograder Container Limits
Hard Resource and Execution Bounds
Constraint Outcome When Reached
256 MB RAM Process terminated; not counted
Runtime exception Process crashes; not counted
50% of 1 CPU core Caps compute throughput
No disk / network Read-only sandboxed container
400 falling blocks Game stops cleanly; score kept
15 min wall time Game stops cleanly; score kept
Python Runtime
The grading container runs vanilla Python 3.7.
Avoid language syntax introduced only in newer
Python releases (such as match/case) and avoid
all third-party imports.
Strategic Consequence
Because play stops at 400 blocks, pure survival
yields a low score. Your algorithm must maximise
points per block while staying fast and
memory-light.

Game Mechanics: Non-Linear Scoring
Line-Clear Points Table
Clearing multiple rows at once multiplies rewards by
4× per extra row (plus 1 point per row dropped):
Rows Cleared Simultaneously Points
1 row (Single) 25
2 rows (Double) 100
3 rows (Triple) 400
4 rows (“Tetris”) 1,600
Incentive for Multi-Row Clears
A single 4-row “Tetris” clear (1,600 points) equals 64
single-row clears. With only 400 blocks available,
clearing single lines one by one limits your ceiling
dramatically.
Implementation Caveat
In board.py, scores = [0, 25, 100, 400, 1600]
only indexes up to 4 rows at once. Never design
setups that clear more than 4 rows in a single
placement.

Modified Mechanics: Discards and Bombs
Two Special Actions
▶ Discard (Action.Discard, 10 per game):
Removes the currently falling tetromino and spawns
board.next immediately.
▶ Bomb (Action.Bomb, 5 per game): Substitutes a
1 × 1 bomb (Shape.B) in place of board.next.
When landed at (bx, by), it destroys all occupied
cells within |x − bx| ⩽ 1, |y − by| ⩽ 1 for zero points,
and drops any overhanging blocks in those three
columns straight down.
Bomb 3 × 3 Blast Neighbourhood
B
Recommended Progression
Ignore Bombs and Discards initially. Build a
strong core Tetris player first; add special actions
only as a later refinement.

Returning Actions: Lists vs Python Generators
Option 1: Single Move or List
Return one action (Direction.*, Rotation.*,
Action.*, or None to skip), or a non-empty list of
actions:
1 return [
2 Rotation.Clockwise,
3 Direction.Left,
4 Direction.Drop,
5 ]
Option 2: Generator (yield, Week 4)
Stream actions lazily one by one without building an
explicit list first:
1 yield Rotation.Clockwise
2 yield Direction.Left
3 yield Direction.Drop
Engine Execution Rule
Actions run only until the falling block lands; leftover
actions are ignored and choose action is called
for the new block. Never return [] (infinite loop).

Search and Heuristic Strategy Overview
Target-State Search
Because future blocks beyond board.next are
unknown, search over candidate landing placements:
1. Test all rotations (0–3) and columns (0–9) — at
most ≈ 40 placements.
2. Simulate each on board.clone() ending with
Direction.Drop.
3. Score the resulting board and pick the maximum.
Lookahead: Extending to board.next tests ≈ 1,600
states (respecting O(bd) runtime bounds).
Linear Heuristic Evaluation
Combine structural features with tuned weights,
E(s) = w1∆S − w2H − w3K − w4B,
where:
▶ ∆S: Score gain (rewards 3–4 row clears).
▶ H: Aggregate or maximum column height.
▶ K: Buried empty holes under blocks.
▶ B: Surface bumpiness P x |hx − hx+1|.
